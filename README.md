# DWS 通用钉钉 Skill

让 AI 助手引导用户用自己的钉钉账号登录，并在授权后介绍和使用钉钉办公能力。基于官方 [DingTalk Workspace CLI](https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli)，不是独立的钉钉客户端，也不提供共享账号。

## 使用流程

安装 Skill → 首次对 AI 说“初始化 DWS” → 检查/安装官方 CLI → 用户本人完成钉钉授权 → 核验组织和账号 → 简短介绍功能 → 按用户指令工作。

普通 Skill 没有安装后自动执行的钩子，必须首次调用才能开始引导。已有有效登录则复用，不要求重复扫码。部分组织需管理员先开通 CLI；所有数据以当前用户可见范围为准。

## 安装

1. 按官方项目说明安装 CLI；已有 Node.js/npm 时可以执行 `npm install -g dingtalk-workspace-cli`。
2. 将本仓库 `skills/dws` 整个目录安装到你所用 AI 工具的 skill 目录。例如 Codex 使用 `~/.codex/skills/dws`，支持共享 skills 的工具可使用 `~/.agents/skills/dws`。目标已有同名 skill 时先备份、再替换，避免同时安装多个同名入口。
3. 在 AI 工具里重新加载技能或开启新对话，输入“使用 dws，帮我登录钉钉并介绍你能做什么”。

仓库不包含 CLI 二进制，不包含任何账号或公司数据。不要把你自己的 DWS 配置目录一起上传。官方 `dws skill setup` 可能替换本定制版入口；更新 CLI 后检查入口仍为本版本。

## 可以直接说

- 查看我公司的组织架构。
- 找一下负责采购的同事。
- 列出我今天的日程和待办。
- 找到我能访问的项目文档并总结。
- 查询这个 AI 表格中的记录。
- 总结我最近一次会议的听记。

发送消息、修改数据、审批、删除与共享均按用户明确授权执行。欢迎流程仅检查身份，不自动扫描企业数据。

## 公开版改动

- 补上缺失 CLI、未登录、已有登录、多组织、过期与授权失败的引导。
- 不预置作者身份、组织架构、内部资源 ID、内部地址或渠道码。
- 登录完成后提供自然语言能力介绍；不把登录成功等同于所有产品权限已开通。
- 用当前 CLI 的 help/schema 获取操作契约，避免把庞大、过期或带本机信息的参考目录整体打包。
- 保留 Apache-2.0 许可证与上游来源声明。本定制内容同样按 Apache-2.0 提供。

## 验证范围

已用本地 DWS v1.0.60-beta.1 的实际帮助核对认证、profile、当前用户和 Schema 命令，并检查技能结构、引用及发布文件。尚未使用独立新账号、另一家公司进行首次登录验收。

发布前建议用全新系统用户或独立测试环境验证：未安装 CLI、无登录、已登录、多账号无默认、企业未开通、单产品权限不足、授权取消，以及账号切换后不沿用旧公司数据。测试凭证只留在测试环境。
