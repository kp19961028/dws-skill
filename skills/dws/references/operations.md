## 查询契约再执行

1. 已知服务时用 `dws <service> --help` 找到实际命令；存在匹配意图的公开 `+` shortcut 时优先使用。
2. 用 `dws schema --cli-path '<实际命令路径>' --compact --format json` 查询叶子参数、约束、权限及确认语义，并用叶子 `--help` 核对可接受的 flags。旧版缺少 schema/compact 时按当前帮助降级，不猜未暴露命令。
3. 使用真实查询获得的 ID，显式附加所选 `--profile` 与 `--format json` 执行。用户提供链接时先按当前产品命令解析资源类型，不把 URL 中任意片段当作对象 ID。
4. 对分页读取检查游标/hasMore/总数/部分失败标记，并按实际帮助翻页。无分页支持或权限不足时标记结果不完整，不静默声称全量。批量遵循当前命令上限，且每批不超过 30 条。
5. 解析 stdout 和 stderr 的结构化结果。业务失败即使退出码为 0 也不算完成；不要将完整原始响应或调试日志复制到公开输出。

不要为普通请求读取 `schema --all`。不确定返回信封时先看真实结构，不用过滤器把数据误过滤成空结果。

## 组织架构

先核验 profile 和当前用户的可见组织，再通过 `contact dept --help` 或 `contact` 下对应公开 shortcut 定位部门查询。根部门 ID 必须来自返回结果或当前命令明确记载的根节点约定，不能猜值。

用户要全公司架构时递归查询可见子部门，以部门 ID 去重防循环，保留父子关系。仅在用户要人员清单时展开成员。人数注明含子部门与否，不把人员汇报关系、部门负责人和管理角色混为一谈。遇到分支无权限，保留该分支“未能读取”的标记和原因。

## 写操作与失败

先解析目标组织、账号、对象、内容和影响。用户已明确授权的具体写操作无需重复确认；新增的删除、群发、权限变更等影响需要得到对应授权。当前 CLI 要求确认时，先展示必要预览，获得覆盖该操作的授权后使用 `--yes`。`confirmation_required` 不是网络故障，不能盲目重试绕过。

写操作超时或结果不明先查询状态，避免重复消息、重复审批或重复记录。权限拒绝按当前平台提示处理，不能切换为其他人的身份重试。
