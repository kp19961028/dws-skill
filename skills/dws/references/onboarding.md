# 首次使用与登录

## 1. 检查依赖

执行 `dws --version`。找不到命令时，说明 skill 是 AI 操作指南，还需要官方 DWS CLI。

官方项目与安装说明：
https://github.com/DingTalk-Real-AI/dingtalk-workspace-cli

有 Node.js/npm 的环境可按官方说明安装：

```sh
npm install -g dingtalk-workspace-cli
```

没有 npm 时，根据操作系统从官方 Releases 选择对应构建，不随意猜下载地址或引入第三方安装器。用户要求安装时可完成对应安装；涉及系统授权交给用户本人。已安装时不为引导自动升级，也不执行 `dws skill setup` 覆盖这个定制入口。

## 2. 检查已有身份

```sh
dws profile list --format json
```

解析真实结构，不假设字段一定嵌套在某个位置。用户指定账号优先，否则使用明确的 `isCurrent=true`；多候选无明确选择时列出组织和账号显示名称，请用户选择。不要展示手机号、邮箱、Token 或完整内部标识符。

对选中项使用返回的稳定 profile：

```sh
dws auth status --profile '<返回的 profile>' --format json
```

`auth status` 可能刷新令牌。认证有效则跳到第 4 步；未登录/需重新授权则进入第 3 步。网络故障、服务拒绝或解析失败不等于未登录，不清空凭证。没有账号时直接进入第 3 步。

## 3. 用户本人授权

先查当前版本帮助：

```sh
dws auth login --help
```

优先设备流，便于聊天里给出官方授权入口，且无需本地回调监听：

```sh
dws auth login --device --format json
```

已有明确目标组织需要重新授权时，按照当前帮助追加选中项的 `--profile`。在宿主可达的本机环境、用户希望使用浏览器回调时，可按本机规则使用 `dws auth login --format json`。

向用户说明：“请打开以下官方钉钉授权地址，用你自己的账号登录并选择公司。完成后我会检查连接状态，再介绍可用功能。”只转达 CLI 实际返回的官方 URL 和本次设备授权码，不编造二维码、链接或口令。设备码只用于当前授权，不保存到仓库。

保持登录进程，按宿主工具支持获取增量输出，授权结果未返回前不执行依赖登录的业务命令。若当前工具无法保持进程，给用户同一条命令在其本机终端完成；不要声称后台仍在等待。用户取消或授权超时后停止该流程，不循环弹出登录。

不要默认附加 `--recommend` 批量授予推荐权限，也不要让用户把密码、验证码、Token 发进聊天。

特殊错误：

- 公司未开通 CLI/企业未授权：按官方页面提示由用户申请管理员开通，开通后重试。不能承诺所有公司都能直接使用。
- `CHANNEL_REQUIRED` / `channel_not_allowed`：需要服务方为真实宿主和组织配置允许的渠道。公开版不内置渠道码，也不遍历渠道尝试绕过。
- 登录成功但产品权限不足：说明仅该能力尚未授权，按实际错误提示完成所需授权，不重复重置整个账号。
- 网络故障：保留错误摘要，修复网络后重试，不用 `auth reset`、`logout` 清空其他账号。

## 4. 核验并欢迎

重新运行 `profile list`，按本次登录返回的身份定位对应稳定 profile；必要时让用户选择。对该 profile 执行 `auth status`，核对实际认证结果。不能仅凭进程退出码或存在缓存宣称登录成功。

从核验后的响应中提取组织和账号显示名；缺少姓名或组织名且需要识别时，先检查帮助，再最小化查询：

```sh
dws contact +me --help
dws contact +me --profile '<返回的 profile>' --format json --fields name,dept,org
```

如果当前 CLI 不支持 `+me`，检查 `contact user get-self --help` 后使用实际支持的参数；显示结果仅保留姓名、组织和必要部门，不展示其他个人字段。如果通讯录查询被拒，说明“登录已完成，个人通讯录读取尚未授权”，仍可介绍通用功能，不冒充已验证该产品可用。

用 [能力介绍](capabilities.md) 输出欢迎说明，并邀请用户选择第一件事。用户原本已有明确任务时，欢迎说明压缩为一两句，接着完成原任务，无需再问“要做什么”。不为欢迎说明逐一探测所有产品或导出企业架构。

同一会话不重复长篇欢迎；用户要求介绍能力时再展示。新会话仍核验当前身份，但不依赖仓库中保存登录状态。
