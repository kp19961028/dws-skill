# DWS 通用钉钉助手

通过本机官方 `dws` CLI，以用户自己授权的账号访问钉钉。不预设公司、人员、管理员身份、组织 ID、渠道或业务数据。

## 首次使用与身份

用户首次使用、要求初始化/登录/切换账号，或认证失效时，读取 [首次使用](references/onboarding.md) 并完成引导。用户只问功能或安装方案时可直接解释，不强迫登录。

安装 skill 不会自行执行命令；首次调用才启动引导。已登录时复用经核验的当前账号，不强制重新授权。先确认认证成功，再介绍功能；不要把授权链接已打开当作登录成功。

每次新会话或组织/账号变更后，通过 `dws profile list --format json` 重新解析身份。使用明确指定的账号，或 CLI 明确标记的 `isCurrent=true`。多个候选且无明确当前账号时，请用户选择，不取第一项、不按最近使用猜测。后续业务命令显式传真实返回的稳定 `--profile`，不持久切换全局账号，除非用户要求。

不把旧账号的对象 ID、查询结果或对话中的组织架构套用到新账号。能力以当前用户、当前组织、实际权限和本机 CLI 为准。

## 能力与执行

- 登录后用 [能力介绍](references/capabilities.md) 简短说明用途和自然语言示例。
- 用户提出具体任务后按 [操作路由](references/operations.md) 定位服务，按任务范围读取数据或执行操作。
- 能力清单不是支持范围的上限。用户请求未列出的模块、找不到命令或询问新增功能时，先按 [官方能力发现](references/discovery.md) 核查本机 CLI 和官方 GitHub，再判断是否支持。
- 所有钉钉业务访问走 `dws`，不直接拼 HTTP 请求或读取浏览器登录态。官方登录页面由用户本人授权。查阅公开的官方 GitHub 文档、源码及发布信息可使用网页或 GitHub 工具，不属于钉钉业务数据访问。
- 数据命令使用 `--format json`；`--help` 和版本检查按 CLI 自身格式读取；事件流按实际帮助使用 `ndjson`。
- 不编造 ID、参数、分页能力或命令。用当前叶子 `--help`、`schema --compact` 核对；参数取自用户明确输入或真实查询结果。
- 登录只授权连接，不意味着授权读取全公司通讯录、聊天或文件。欢迎流程不遍历企业数据；有具体任务后再查询所需内容。
- 发送消息、邮件、审批、修改、删除或共享必须在用户明确授权的目标与范围内。已有授权足够具体时不重复询问；目标、内容或影响不明确时先准备预览并补齐信息。按 CLI 的 risk/confirmation 契约使用 `--yes`，它不能替代用户授权。
- 不在聊天中索要密码、验证码、Token 或 AppSecret，不复制其他人的认证目录。凭证由 CLI 管理，不写进 skill、仓库、日志或产物。
- 不默认设置自定义应用、服务端地址、代理或渠道码。不因授权失败尝试其他身份或渠道；说明实际错误及用户/管理员需要做的步骤。
- 区分成功、未授权、部分结果、无结果与请求失败；业务写入应核对返回结果，超时先查状态，避免盲目重复提交。

此版本新增通用首次使用流程，重新编写身份边界与操作路由。底层能力来自 DingTalk Workspace CLI；保留仓库中的上游 NOTICE 与许可证。
